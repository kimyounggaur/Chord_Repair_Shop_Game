# S07 UI 준비 — 구현 대기

2026-10-19. 원본 M00/S07 및 design3/5/6/8/12.1–12.2를 실제로 읽은 계획이다. **S06 게이트 전에는 S07 소스를 구현하지 않는다.** 기준 fixtures/정답/질문 문구는 바꾸지 않는다.

## 화면과 진행

- 동일 OrderRunner의 현재 Order는 session.orderId로 결정한다. 초기 draft도 orderId에 맞춰 로드한다. 화면은 session.screen/SET_SCREEN으로 통합한다. 화면 이동도 저장 checkpoint가 필요하므로 reducer/런타임 담당과 조율한다.
- `initialReceipts`/완료 receipt 목록을 받아 첫 과정에서는 canOpenOrder가 허용하는 첫 미완료 주문만 연다. 8고유완료 뒤 자유 재방문. completed의 명시적 다시 연습은 새 attemptId/seed이며 첫 시도 기록을 덮지 않는다.
- CR01/02 editableSlots=[1], CR03~08은 세 슬롯 전체. 이동/편집 횟수/시간/입력 모드는 판정·보상과 무관하다.
- S04의 `currentRole`은 target membership에 해당하지 않는 음만 '살펴볼 음'이라고 표시한다. 이것을 CR07/08에 그대로 확장하면 잘못된 슬롯이 자동 노출된다. optional 주문 초기 화면에서는 중립적인 물리 부품 번호와 현재 음만 보여 주고, 역할·거리 설명은 명시적 관계 도구에서 제공한다. 특정 슬롯을 강조하거나 slot index를 실제 역할이라고 단정하지 않는다. 독립 음악 검토자와 이 위험 및 처리방향을 확인했다.
- CR03의 다른 근음/5음7반음 소개는 학습 안내로 표시하고 봤다면 수리 도움1을 기록한다. CR04의 B♭/A♯ 보조 건반명은 MIDI70의 같은 입력을 뜻하며 슬롯은 문맥 B♭4를 쓴다. CR05/06 자동 힌트 없음. CR07 이전 선택형 복습은 세 역할/3음·5음의 관계만 다루며 오답 슬롯을 가리키지 않는다. CR08 시작음을 임의의 조성/화음명으로 부르지 않는다.

## 튜토리얼 T0–T7

시간 제한 없이 문서 흐름 안의 안내 카드로 제공한다. 고정 말풍선/오버레이가 작업을 가리지 않는다. 언제든 건너뛰기/다시 보기, 소리 없이 보기 가능.

| 단계 | 표시/행동 | 증거 처리 |
|---|---|---|
| T0 | 소리 켜기/소리 없이 시작, 작은 기기 음량 안내 | 접근성/음소거는 힌트 아님 |
| T1 | 주문 C 장3화음, 주문서 확인 | 목표 이름 자체는 도움 아님 |
| T2 | 오르골의 세 음, 원래 듣기 또는 음이름 보기 | 보기만 해도 진행 |
| T3 | 현재 C/E♭/G의 역할 안내 | CR01 guided 범위, 정답 키 강조 없음 |
| T4 | 오늘은 3음을 바꾸기, 현재 슬롯 탭 | CR01 질문의 유지된 C/G를 사실상 공개하므로 EXPOSE_REFLECTION_ANSWER |
| T5 | 원하는 음을 자유롭게 고르기 | 사용자 변경만 SELECT_PITCH, 자동 정답 입력 없음 |
| T6 | 준비되면 수리 확인 | CHECK 경로 그대로 |
| T7 | 무엇이 바뀌었는지 비교/설명 | 관계 질문 응답/skip/해설 요청 뒤에만 상세 설명 |

튜토리얼 카드 열림은 일시 UI 상태이며 reload 때 자동으로 정답 안내를 재생하지 않는다. 이미 본 답/도움 증거는 세션에 즉시 기록하고 보존한다. 추가 tutorial UI 저장 필드가 필요하면 S08 schema 확정 전에 담당자와 조율한다.

## 도움/질문 답 노출 지도

copy는 text와 `revealsReflectionAnswer`를 함께 반환한다. 숫자·변경역할·정답 이름이 실제 질문 답을 직접 보여 주는지 문항별로 판단한다. false를 일괄 적용하지 않는다. 도움 3 시범은 모든 주문에서 level3 + 노출이며 demoSnapshot을 별도로 보존하고 `내 상태로 돌아가기`/`시범 상태로 연습` 선택을 제공한다.

| 주문 | 질문의 핵심 답 | 도움1 정책 | 도움2 정책 |
|---|---|---|---|
| CR01 | 유지된 C/G | 일반 장3화음 조건만은 답 노출 아님; '3음만 변경'은 노출 | 이전/현재 변경을 드러내면 노출 |
| CR02 | C→E♭ 3반음 | 단3음3반음을 말하면 노출 | 3반음 목표 거리/이름을 보이면 노출 |
| CR03 | 근음→3음4반음 | '근음만 바뀌고 규칙은 같다'만은 비노출; 4반음은 노출 | F→A4반음은 노출 |
| CR04 | 3음B♭ | 'G에서3음의 거리를 확인'은 비노출 | G→B♭3반음은 노출 |
| CR05 | 3음반음상승 | 장3화음 일반조건은 비노출; 초기와 비교해 바뀐역할/반음 방향은 노출 | 현재/목표 거리비교가 방향을 드러내면 노출 |
| CR06 | 3과7 | 단3음3/5음7을 말하면 노출 | 두 거리도식은 노출 |
| CR07 | 5음7 | 관계복습/도움에5음7이 있으면 노출 | 5음7 도식은 노출 |
| CR08 | F와A♭ | 목표근음F/단화음 일반조건만 비노출 | F→A♭ 이름이 나오면 노출 |

반음 도식은 출발점 포함 음점 수와 사이 간격 수를 구별한다. 현재 두 음 선택과 목표 거리 확인은 사용자 선택을 자동 정답으로 옮기지 않는다. 반음도움·해설은 repair/reflection 최대 도움을 별도로 기록한다. SHOW_EXPLANATION은 첫 응답 이전이면 노출을 기록하며 질문오답/skip도 보상을 그대로 유지한다.

## 피드백과 결과

- 기본 피드백은 주문 조건+다음 탐색 행동, 구조화된 grade code의 첫 관련 원인부터 설명한다. 여러 음을 빨갛게 표시하거나 자동 복원하지 않는다.
- CR01 D4 피드백은 원본의 '장3화음의 3음은 근음보다 4반음 위에 있어요. C에서 하나씩 세어 볼까요?'를 올바르게 띄어 쓴다. 이 문구가 다른 주문의 질문 답을 공개하는 경우에도 노출을 기록해야 한다.
- 수리 정답은 '주문 조건에 맞아요'만 먼저, 원본 관계 질문/seeded option DOM 순서 그대로. 응답 뒤 원래/현재 MIDI와 목표역할을 기준으로 해설한다. CR07은5음6→7, CR08은근음E→F와 유지된A♭/C를 설명한다. S04의3음 전용 해설을 모든 주문에 그대로 쓰지 않는다.
- 완료와 개념확인을 별도 표시한다. 첫제출/최종성공, 수리도움/질문도움, 첫개념답/노출을 구분하며 단일 음악실력 점수나 연주향상 주장은 하지 않는다. 접근성 옵션은 불이익이 아니다.
