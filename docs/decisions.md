## D001 — 현재 PC에서 별도 작업 폴더 사용

사용자가 현재 kimyounggaur PC에서 작업하고 오프라인 DESKTOP-FVHJSEO에 접근하지 말라고 지정했다. 작업 경로는 `C:\Users\kimyo\Documents\Codex\2026-10-19\task-4\chord-repair-shop`이다. D 드라이브와 OneDrive 원본은 읽기 전용으로 조사했다. 원본 백업을 편집하거나 기존 다른 게임을 덮어쓰지 않는다.

S00 문서 작성 시 `git status --short`에는 새 scaffold 파일만 untracked로 표시되었다. `origin`은 지정 GitHub URL이며 `main`에는 아직 commit이 없었다. 이는 이 로컬 저장소의 당시 관찰값이며 원격 저장소 전체 이력이 없다는 독립 증거로 확대하지 않는다. 원격 이력 검사는 주 실행 에이전트가 별도 수행한다.

## D004 — 에셋 패키지의 범위

ZIP은 24,405,812바이트, 105개 항목이며 최상위 경로는 `chord-repair-shop/`이다. runtime 파일 50개와 적용 안내·주문별 아트 매핑·검증 스크립트가 있다. `package.json`, `src/`, `.git/` 게임 소스는 없다. 매니페스트의 runtime 합계는 735,434바이트, 초기 그림 합계는 72,996바이트다. 이 수치는 앱 전체 전송량이나 실제 프레임 성능 측정이 아니다.

패키지 안내는 그림 전용 산출물이라고 명시한다. 오디오는 Web Audio 합성 범위이며 실제 오디오 파일이 있다고 기록하지 않는다. 손님/악기 그림 매핑은 정답·슬롯 역할·음색 판정에 사용하지 않는다. S00에서는 원본을 확보했으며 앱 통합은 S10 등 해당 단계에서 검증한다.

## D005 — 도구와 구조

React + TypeScript strict + Vite, Vitest/Testing Library/Playwright 및 npm 단일 lockfile을 사용한다. 실제 고정 버전과 검사 범위는 `toolchain.md`에 기록한다. 개발 포트 5486, preview 포트 4486은 사용자 지정값이다. 음악 도메인은 순수 함수이며 UI → 세션 → 음악 의존 방향을 유지한다. AudioService는 정답을 모른다.

자체 lint는 도메인 import와 unsafe escape를 검사하는 최소 검사다. 광범위한 코드 품질/접근성 검증을 완료했다고 해석하지 않는다. 아직 테스트가 없는 script 그룹은 NOT RUN으로 남긴다.
