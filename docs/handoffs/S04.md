## 한계와 다음 단계 계약

실제 손가락, iOS/Android 기기, VoiceOver/NVDA, 출력 소리 청취는 **NOT RUN**. Playwright의 모바일/터치 에뮬레이션은 실기기가 아니다. 200% 검사는 CSS zoom이며 실제 브라우저 메뉴 확대와 동일하다고 주장하지 않는다. 자동화는 무음 adapter를 썼고 오디오 동작은 S05/S06에서 검증한다. 저장은 메모리 상태만이다. S04 주문 목록은 CR01만 열리고 S07에서 순차 진행을 연결한다.

`App` 주입점: `initialOrder`, `initialSession`, `services`, `onSessionChange`, `onComplete`. 모든 세션 이벤트는 하나의 dispatch wrapper로 전달된다. GRADE를 순수 executor로 처리하고 CANCEL_AUDIO/FOCUS/COMPLETE 및 외부 명령을 실행한다.

`WorkbenchServices`는 `enable():Promise<boolean>`, `previewNote(midi)`, `playOriginal(snapshot)`, `playCurrent(snapshot)`, `compare(snapshot)`, `arpeggiate(snapshot)`, `stopAll()`, `status()`, optional `onCommand(command,state,order)`다. AudioSnapshot은 `{orderId,attemptId,revision,original,current}`의 복사된 MIDI 배열이며 정답은 전달하지 않는다. S05/S06 audio가 이 계약의 adapter를 제공한다.

S08 저장은 `onCommand`의 SAVE/COMPLETE에서만 수행한다. `onSessionChange`나 GRADE 관찰 상태를 무조건 저장하지 않는다. `onComplete`와 onCommand COMPLETE 둘에 중복 DB 쓰기를 연결하지 않는다. S07은 screen을 session.screen/SET_SCREEN으로 옮기고, S08은 복원 orderId에 맞는 Order와 draft를 주입해야 한다.
